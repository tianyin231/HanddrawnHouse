## 使用

启动 `npm start`，打开 `/viewer/survey.html`，或从三维首页左侧进入。查看页面无需 Three.js；三维首页仍按 README 安装依赖。现有服务器保持只监听 `127.0.0.1`，没有新增远程访问、账户或后端存储。

页面从同一组参数和平面 JSON 生成楼层示意。选择房间可对照含墙分配尺寸和扣墙矩形范围估算；完成面净尺寸显示「尚未提供」，不以估算替代。主卧当前示例为含墙 4000 × 4500 mm、扣墙估算 3670 × 4170 mm；这些数值不是现场测量或成品家具下单尺寸。

42 项记录覆盖边界、分间、标高、墙厚、通道、楼梯、厨房南窗及邻房数据。每项需要数值、单位口径、测量日期、测量人和测点／照片依据。尚缺的实测值不填默认数值；来源分别标为用户约数、图纸含墙、暂定、设计建议、设计目标或缺失。

每个记录项当前保留一份记录，多测点及历次结果应通过备注和导出的分版本文件保存。尺寸页不是完整测绘数据库。门窗逐樘及房间完成面的明细行包含在 CSV 复测清单中，目前不提供逐樘在线录入表。

## 记录、备份与应用边界

浏览器以 `HanddrawnHouse:measurements:v1` 保存当前记录，只属于当前浏览器和网址来源；换设备、换端口、浏览器清理或隐私模式可能使记录不可用。记录不会自动上传或修改仓库。请使用「导出记录 JSON」备份，再在另一设备导入。

导入会先验证整个文件，出现未知项目、重复项、单位错误、非有限数字或无效日期时拒绝整批，不覆盖已有记录。和本地同名的记录在确认后替换。文件限制为 1 MB；测量人及依据各最多 500 字，备注最多 2000 字。存储失败时页面明确提示导出，不声称已持久保存。

只有口径一致且记录时的模型基准未变化，才展示相对模型的差值。口径不同或模型参数已更新时显示需复核，不直接比较。差值不作为允许误差、规范结论或自动修改依据。负标高允许记录；未知高度不会用「一层」转换为默认高度。

导出的 CSV 包含全部 42 项台账、31 个空间和 50 个洞口，不随当前筛选遗漏；使用 UTF-8 BOM、CSV 引号转义和公式前缀防护。JSON 校核报告只描述参数与平面检查，不混入未经复核的现场记录。打印会临时展开全部台账项，随后恢复当前筛选；实际排版和分页仍需在目标浏览器确认。

## 自动校核覆盖

`viewer/dimension-audit.js` 是浏览器与 Node 共用的无依赖只读模块，`scripts/audit-dimensions.mjs` 从脚本所在仓库读取数据，不依赖运行时工作目录。

覆盖毫米单位、数值有效性、上下层标高闭合、偶数折返踢面、楼梯参数和平面缓存一致性；覆盖墙厚、主体外墙定位、房间含墙及扣墙缓存、洞口宿主／边界／高度／重叠和空间连接引用。检查改参数但未重建平面的常见失配。

保护既定约束：两层套卫、门廊上楼、厅堂不直接通往楼梯、取消临院楼梯墙、二层前院挑空、附属间门前 2 米净通道，以及厨房南窗与参数一致。算法复用现有轴对齐矩形和平面语义，不替代任意形状 CAD 校验；新增斜墙或非矩形房间必须先更新算法，不能继续沿用矩形净空估算。

检查通过固定保留：

```json
{
  "data_status": "pass",
  "model_status": "needs_review",
  "scope": "parameters_and_plan_json_only",
  "engineering_acceptance": "not_assessed",
  "binary_models_checked": false,
  "field_measurements_verified": 0
}
```

退出码：0 为已覆盖的数据一致，1 为数据冲突，2 为读取或命令参数错误。报告不是全部生成字段的逐字匹配，也不证明现场可施工、楼梯净空、安全防护、采光或通风达标。

## 本轮验证

在 Node.js 22.16.0 下运行 `npm test`：41 项测试通过。包含原始两层数据、只读深冻结、参数变化、负数／NaN、奇数踏步、楼层和墙体缓存、洞口重叠、院子挑空与动线回归，以及记录口径、日期、单位、批量导入和 CSV 防护。

`npm run check:dimensions`：当前 31 个空间、50 个门窗洞口、42 项现场记录项，未发现已覆盖的数据冲突。三个输入 JSON 的 Git blob SHA 与基准提交一致；本阶段没有通过改输入去消除告警。

离线浏览器检查使用 Chromium + Playwright，覆盖 1440 × 1100、390 × 844、768 × 1024、360 × 780 四种视口：加载、楼层切换、房间选择、筛选、记录保存逻辑、记录序列化后重新挂载、导出内容、不同口径提示、无效导入的原子拒绝、打印时完整台账，以及读取失败、参数损坏、存储损坏和写入失败分支。四种视口未发现页面横向溢出或脚本异常。

**离线验证边界：**执行环境的浏览器策略阻止原生网址导航，因此采用空白页面载入本项目的真实 HTML、CSS、JS，注入固定 JSON 并模拟 fetch、localStorage、下载及打印。这只证明 DOM／组件逻辑与响应式布局，不是实际网址下的端到端测试；不证明原生持久存储、文件下载、打印分页、手机触摸或 iOS 浏览器已经通过。HTTP 静态资源可由本地服务返回，但浏览器原生导航未完成。没有修改浏览器策略。

可选复现（需要 Python、Playwright 和可用 Chromium；不属于 npm 运行依赖）：

```text
python tests/survey-browser-offline.py --browser /path/to/chromium --output /path/to/qa-output
```

不指定 `--browser` 时优先查找系统 Chromium，否则使用 Playwright 的浏览器。测试在输出目录生成截图及 `browser-results.json`，不会修改参数和平面。目标电脑仍应通过 `npm start` 做原生网址、刷新后记录恢复、真实下载、打印预览和触控验收。

本轮没有 Blender 运行环境，没有重建或回读 `house.blend`／`house.glb`，没有执行原有 `verify_house.py`。原二进制文件保持不变，不能把本轮 Node 检查当作原生实体检查通过。
